# Research before paths, rigging, animation, and export

This pass precedes implementation of the four milestones requested on 2026-10-08. It builds on the comparative interface study in [the UX research](11-editor-ux-research.md) and reads the official documentation, runtime implementation, CLI rigging grammar and existing executable probes. Public workflows inform authoring; runtime source plus tests establish serialized behavior. Neither supplies access to Rive's closed editor UI implementation.

Rive Node transforms are translation/rotation/scale; Studio v1 can also retain shear. The exporter must reject shear or implement an explicitly tested conversion. This milestone uses rejection with a node-specific diagnostic; it must not silently decompose a sheared matrix into a different image. Asset metadata carried in a project is not proof of asset export support. The export subset must be stated and tested separately from full Rive feature parity.

The project schema needs a versioned addition for paths, rigs, keys and machines. Existing v1 projects must be validated before an explicit lossless migration; unknown future fields/versions remain errors. Deletion must now consider skin references, animation tracks, state/transition references and listeners. Preview instances and editor-only visibility must not silently become serialized runtime behavior.

## Findings during official-runtime validation

The first return-transition oracle failed because a Rive animation writes only its keyed properties (`AnimationStateInstance::apply` delegates to the linear animation). Studio deliberately evaluates each pose from authored defaults. The compiler now fills each animation's missing properties from the artboard's animated-property union with explicit constant default keys. The source project is unchanged; switching states now reproduces Studio's default-restoration semantics.

Drawable declaration order is the reverse of Studio's ascending sibling paint order. The compiler traverses siblings in descending order; overlapping translucent paint is included in the pixel oracle to detect order errors. Cubic easing interpolators occupy artboard component slots even though they have no geometric parent.

The tested web binary accepts the older `StateMachineListenerSingle` representation for click (enum value 6). The first pointer test did not fire while using an inactive high-level player; that failure does not isolate a serialization problem. Export uses the single-listener representation already exercised by the prior research and now verified through actual browser pointer events. The listener test explicitly plays the state machine while stopping the render loop for deterministic zero-time application; an inactive high-level player is not a valid pointer-listener test.

Runtime immediate transitions settle in a bounded loop; a trigger can be used once per layer per advance. Studio implements bounded settlement and consumes triggers used by a transition before examining the next state. A continuously enabled transition cycle produces a preview diagnostic.
