## Research before implementation

[Live retrieval provenance](../research/studio-navigation/sources.json) records URLs, HTTP outcomes, sizes and hashes. Sources were read alongside the current model, history, animation evaluator, reparent operation, compiler and existing browser tests.

- [Rive selection/navigation](https://rive.app/docs/editor/interface-overview/selection-and-navigation) documents grouped selection, hierarchy traversal, pan, focal zoom and Fit. [Sidebar documentation](https://rive.app/docs/editor/interface-overview/sidebar) documents customizable panels, collapse and layout reset. These inform workspace controls, without establishing Rive's touch behavior or copying its interface/assets.
- [WAI window-splitter guidance](https://www.w3.org/WAI/ARIA/apg/patterns/windowsplitter/) informs named, focusable separators, controlled-panel references, width ranges and arrow-key adjustment. Its published note says the pattern review/example is incomplete; this is design guidance, not certification.
- [WAI treeview guidance](https://www.w3.org/WAI/ARIA/apg/patterns/treeview/) informs expandable hierarchy and separating focus from selection. Evir retains ordinary labeled buttons and disclosure controls; it does **not** claim to implement the complete ARIA tree widget.
- [WCAG dragging movements](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html) requires a single-pointer alternative to non-essential dragging; keyboard support alone does not satisfy that criterion. Panel widths also have numeric inputs. Layer organization uses explicit destination/stacking controls without requiring drag-and-drop. Existing Pan, zoom buttons and Fit remain alternatives to two-finger navigation.
- [MDN pointer-event pinch gestures](https://developer.mozilla.org/en-US/docs/Web/API/Pointer_events/Pinch_zoom_gestures) informs pointer tracking and cancellation. Evir preserves the world coordinate under the moving midpoint and restricts custom touch handling to the stage.
- [Material bottom sheets](https://m3.material.io/components/bottom-sheets/overview) describes secondary content anchored to the screen bottom in its returned metadata; the detailed page is a JavaScript shell, so no detailed gestures were inferred. The user's explicit sheet preference determines the presentation. [Reduced-motion guidance](https://developer.mozilla.org/en-US/docs/Web/CSS/@media/prefers-reduced-motion) informs disabling non-essential movement.

The attempted Penpot layers URL returned 404 and supplies no evidence. Earlier case studies remain separately documented. No new renderer/AI claims follow from these interaction sources.

## Using the controls

**Desktop panel widths:** drag a Layers/Properties panel's inside edge, or focus that edge and use Left/Right arrows (Shift moves 30 pixels). Home/End reach the available limits; Enter hides that panel and returns focus to its rail button. For a single-pointer alternative, open the zoom/view flyout and enter a width between 180 and 420 pixels. The two widths share a budget that leaves at least 240 pixels for the stage. Reset panel layout restores default widths and opens both panels. Width preferences recover from browser storage and adapt to the viewport; they never enter `.evir-project` or `.riv` files. Mobile drawers retain their existing adaptive width.

**Layers:** use each group's disclosure to collapse or expand its descendants. Left/Right keys on a layer collapse/expand or move focus to a parent/child. Up/Down, Home/End keep the existing selection-navigation behavior. Search exposes matching layers together with their ancestor path without changing collapse preferences. A direct stage selection expands its ancestors so its layer is visible. Depth indentation is bounded so deep names still have usable space.

Select one or several layers, then choose **Organize…**. The **Multiple** toggle retains selections when tapping another layer, including on touch devices without a Shift key. Pick an unlocked destination group/bone or the artboard root, and choose front/back of that destination. Selected ancestors carry their descendants once; the operation preserves base world transforms, source IDs and relative order within the selected roots. Undo restores the whole operation in one step. Descendant cycles, locked ancestors, singular destinations and incompatible bone attachments reject the transaction atomically. Changing parent spaces with relevant animation keys requires key rebasing and is rejected with a custom error; stacking within the same parent remains available. General affine source transforms are preserved, but a reparent can create shear. The existing `.riv` compiler continues to reject shear with an explicit diagnostic; this does not expand the supported Rive transform subset.

**Touch stage:** two fingers pan and zoom around their moving midpoint, clamped to 10–400%. A second finger rolls back an in-progress object/control move or pending Pen gesture before navigation starts. One remaining finger cannot inherit an object drag; lift all fingers before editing again. A third finger pauses navigation. An incidental finger cannot move or finish a mouse/stylus drag; ordinary edits track their owning pointer. Pointer cancellation, lost capture, blur and stage resize clear gesture state. Interact-mode touch listeners activate on release; adding a second finger cancels the pending tap, so starting navigation does not accidentally fire a click listener. Mouse interaction retains its existing behavior.

**Sheets and feedback:** organization, project replacement and shortcuts use bottom-anchored sheets, full width on compact screens. Contextual panels still use side drawers. Sheets retain visible cancellation, Escape, contained keyboard focus and return focus; errors live in the active sheet's top layer. Native HTML dialog semantics supply focus containment, while Evir supplies the presentation—there are no browser alert/confirm/prompt dialogs. Sheets, drawers and toasts enter gently; reduced motion disables the transitions/animation. Pen action space is reserved so showing a draft cannot resize the stage and shift the camera mid-gesture.

Try the default Little explorer: create a Group, collapse Explorer, find Body with search, clear the search, expand Explorer, select Body, then turn on Multiple and select Chest light, and move the selected details into the new group through Organize selection. Undo restores their previous parents. Existing original gallery studies remain available for paths, rigging, easing and typed interactions; each future supported engine feature should add a corresponding original study rather than relabel an unsupported feature as shipped.

## Acceptance and practical limits

`npm run test:editor` includes six browser workflows and 31 unit tests. The [navigation browser acceptance](../tests/editor/navigation-browser.cjs) checks five portrait/landscape/desktop sizes, keyboard/pointer/numeric resizing and recovery, collapse/search/hierarchy focus, bulk organization under affine parents, atomic locked rejection, one-step undo and feedback inside sheets. Chromium touch dispatch checks provisional-edit rollback, focal camera math, one/three-finger guards, cancellation and Interact tap behavior. Automated WCAG checks run in ordinary workspaces and organization sheets. The existing six-size workspace checks, Pen, animation/state-machine, file recovery and export tests remain regression gates. Evidence is recorded under [studio-navigation](../research/results/studio-navigation/).

Browser touch dispatch is not a physical-device measurement. Automated accessibility and keyboard checks do not establish screen-reader usability. The [validation ledger](../research/results/studio-navigation/validation.json) records completed local checks and official-runtime comparisons; these must not be reported as real GPU/mobile or moderated-user evidence.
