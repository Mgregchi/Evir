# Expressive vector character collection

Research and implementation: 16 October 2026 (Africa/Lagos). The user requested examples that show clean contemporary vector art, varied character styles and expressive animation. Momo, Nura and Otto are three original art-directed studies built on Evir's existing vector, animation and state-machine contracts. They introduce no engine schema, hosting target or backend dependency.

## Research and design choices

[Duolingo's published character-animation workflow](https://blog.duolingo.com/world-character-visemes/) describes character-specific expressions, idle blinks/head movement and state-driven reactions. Its separate mouth-state/speech timing system is broader than this work. Evir demonstrates three whole-character expression states; it does **not** implement automated visemes, speech synchronization or Duolingo's complete animation pipeline. The attempted Duolingo shape-language URL returned its Design article landing page; no detailed shape rules were inferred from it.

[Rive bones](https://rive.app/docs/editor/manipulating-shapes/bones), [Animate Mode](https://rive.app/docs/editor/animate-mode/animate-mode-overview) and [easing](https://rive.app/docs/editor/animate-mode/interpolation-easing) explain hierarchical posing, keyed properties and interpolation. These inform separately named facial/limb/clothing layers, cubic easing and a weighted secondary-motion scarf. [Cubic/quadratic path notation](https://developer.mozilla.org/en-US/docs/Web/SVG/Tutorials/SVG_from_scratch/Paths) informs an internal fixture-authoring helper. Its absolute M/L/C/Q/Z notation only constructs these original contours; it is not a public SVG importer. Retrieved response hashes and unsuccessful/discovery responses are in the [source register](../research/characters/sources.json).

The supplied references inform variety, silhouettes and finish. The artwork is independently authored: a soft asymmetric mascot, a rounded human character and a lankier editorial human. There are no traced reference images, stock-art layers or changes to Evir's supplied brand artwork. Every visible character/background detail is an editable filled cubic path; groups and bones organize it. No image or font assets are embedded in these projects. Browser poster PNGs are actual renders of those projects and are separate from the vector sources.

## Meet the collection

| Study | Art direction | Motion and editable details |
| --- | --- | --- |
| **Momo** | Mint mascot with an asymmetric tuft, large eyes, blush, generous smile and soft feet/flippers. | Separate eye/pupil/glint groups, mouth/teeth/tongue, flipper wave, breathing, body squash/stretch and excited bounce. |
| **Nura** | Warm-brown skin, periwinkle hijab, round glasses, sage blouse and a pleated lavender skirt. | Separate head, glasses, eyes, hand/fingers, sleeves and fabric folds; two-bone scarf binding with differing anchor/handle weights for flutter. |
| **Otto** | Longer editorial proportions, dark skin, curly hair, mint headphones, apricot jacket and curved navy trousers. | Independent head/hand/arm posing, blinks, smiling mouth, head nod and lively body rhythm; editable tailoring, sneaker soles and headphone details. |

Find them first on **Examples**, or through the new three-card home-page collection. The home cards load static posters rather than starting three extra runtime players. Gallery previews load when visible, respect reduced-motion defaults and retain the existing pause/offscreen/visibility lifecycle. Use **Expression** to select **Calm**, **Hello** or **Delight**. Selection updates a static pose immediately; **Play motion** animates it. **Reset character** restores Calm and pauses. Keyboard selection and ordinary buttons work without a drag gesture. A failed preview keeps its poster and disables expression/reset controls until Retry succeeds.

Download the editable `.evir-project` and compatible `.riv` from each card. In Studio, inspect named paths and their independent Bézier handles in Design. In Animate, scrub **Calm**, **Hello** and **Delight**, each a two-second loop at 60 fps. In Interact, select **Expressions** and set the number input **expression**: `0` = Calm, `1` = Hello, `2` = Delight. Six direct transitions connect the three states; Reset restores the original value and pose. Intermediate/unmatched numbers retain the current state because this is discrete equality-based selection, not a continuous blend.

Nura's **floating scarf** and **scarf fold** use **scarf root / scarf tip** skin weights. The scarf tip rotates independently of the body/sleeve/head timelines. This demonstrates the existing weighted-path implementation; it does not add general cloth physics, a new weight-painting UI or additive animation layers. Smile scaling and blinks are keyed transforms, not an editable face-morph system. The characters show three styles supported by today's vector foundation; they do not establish support for every art technique or full renderer parity.

## Reproduce and verify

`node apps/web/generate-examples.mjs` rebuilds deterministic sources and exports. `apps/web/character-scenes.mjs` contains the original contour definitions and expression setup. Capture a real poster with `EVIR_CAPTURE_EXAMPLES_ONLY=1 EVIR_CAPTURE_EXAMPLE=momo node tools/capture_site_assets.cjs` (replace the ID for Nura/Otto). Build through `npm run web:build` as usual; the single web host still imports Studio as an independent package.

`npm run test:frontend` checks that all three sources validate, use only vector paths/groups/bones, compile byte-for-byte, reset every declared transition, keep looping and blink; it also checks Nura's differing skin control weights and deformation. `npm run test:web` checks the new expression controls at 320/390/1440 pixels, keyboard selection, real rendered pose changes, live motion, exact-image reset, zero idle frame callbacks, automated WCAG checks, poster fallback/retry and the lightweight home collection. The gallery opens/exports every source in actual Studio and compares selected timelines/states with official Rive Canvas2D/WebGL2 2.44.0 runtimes. Each new character gets declared equality-input transition and reset scenarios, not just a successful file-load assertion. `npm run test:experience` retains broader loading/lifecycle/feedback/SEO checks.

[Fresh evidence](../research/results/characters/) records actual screenshots, source/export hashes, runtime versions, tested poses and command outcomes. Software Chromium/SwiftShader comparisons are not real GPU/mobile, physical stylus or human/assistive-technology results. All physical tests remain postponed; backend remains deferred. [The consolidated plan](25-studio-navigation-and-remaining-work.md) still tracks native stroke paints, general import, richer rigging/blending, text/layout and other open contracts. The separate pressure-brush increment remains in PR #33; this branch starts from current main and does not require that unmerged PR.
