# Freehand shapes

Research and implementation: 11 October 2026. This increment continues the [remaining-work plan](25-studio-navigation-and-remaining-work.md#remaining-work--current-plan). Studio remains an independent package imported into the single hosted web app. No environment settings, source-schema changes or runtime renderer features are added.

## Research before implementation

[MDN coalesced pointer events](https://developer.mozilla.org/en-US/docs/Web/API/PointerEvent/getCoalescedEvents) explains how combining browser events loses drawing detail, and how available coalesced positions recover it. The API has limited availability and requires a secure context; ordinary pointer events remain the fallback. [Pointer Events Level 3](https://www.w3.org/TR/pointerevents3/) supplies pointer ownership, capture, cancellation and `touch-action` semantics. The existing stage restricts custom touch navigation to its own surface. [MDN cancellation](https://developer.mozilla.org/en-US/docs/Web/API/Element/pointercancel_event) identifies interrupted pointer streams. These sources do not establish physical-device latency or stylus quality.

[Rive's Pen guide](https://github.com/rive-app/rive-docs/blob/8879acbbefbf676c8d68d66c2ddfe56c6ee50914/editor/fundamentals/pen-tool-overview.mdx) describes point placement and dragged Bézier handles. It informs compatibility with existing editable paths, rather than evidence that Rive ships this freehand workflow. [MDN cubic paths](https://developer.mozilla.org/en-US/docs/Web/SVG/Tutorials/SVG_from_scratch/Paths) explains the two control points and endpoint slopes of chained cubic segments. [The Douglas–Peucker explanation](https://cartography-playground.gitlab.io/playgrounds/douglas-peucker-algorithm/) describes endpoint preservation and maximum sample-to-segment distance. This is algorithm research, not a competitor feature claim. Attempted Rive/Inkscape manual URLs that returned 404/403 supply no feature evidence. Response URLs, outcomes, sizes and hashes are in [the source register](../research/studio-freehand/sources.json).

The product choices are explicit: a solid-filled shape tool, a reviewable draft, 2 screen pixels of default smoothing, 0.75 screen pixels between retained input samples, at most 4,096 samples and 256 editable anchors. Brush width, pressure, raster ink and variable-width strokes need separate authoring/export contracts and remain open. Existing Pen and numeric control editing offer alternatives to a continuous drawing gesture; this does not replace user or assistive-technology testing.

## Using Freehand

In **Design**, select **Freehand** in the tool rail or press **B** outside a text field. A selected visible, unlocked group or bone becomes the parent. Drag with a mouse, pen or one finger. While held, the stage previews the sampled outline. Release fits editable cubic points. The project remains unchanged until **Finish path** or Enter creates one undo step and returns to Select. The existing **Edit points**, independent handles, fill controls, saving, browser recovery and compatible export then apply normally.

**Drawing options** opens a bottom sheet with smoothing between 0.5 and 8 screen pixels and a **Close the shape** checkbox. Options apply to a released draft and subsequent drawings in this session. Keep drawing or Escape dismisses the sheet without applying changes; focus returns to its trigger. Smoothing is measured at the draft's original zoom, independent of parent scale. Settings and raw samples never enter `.evir-project` or `.riv` exports.

Closed shapes use the actual release-to-start edge; distant endpoints are not silently snapped together. Open paths retain existing solid-fill semantics: filling implicitly connects endpoints, and a straight line has no filled area. This tool does not add a visible brush stroke. A tap or collapsed/over-smoothed shape produces custom feedback rather than an empty committed path. Complexity rejection can be retried with higher smoothing; the requested tolerance is never automatically weakened.

Escape, Cancel path or Undo discards the draft without undoing earlier work. Backspace discards an entire freehand draft; Pen retains its individual-point behavior. Save/export, property edits and mode/tool changes require finishing or cancelling first. Pointer cancellation, lost capture, blur, stage resize and adding a second touch cancel an active drawing. Two fingers retain the existing navigation behavior; neither another stylus nor an incidental finger can finish the owning pointer's drawing. Committed shapes recover from local storage; drafts do not.

## Geometry and resource bounds

Sampling stores world coordinates and filters movements under 0.75 CSS pixels. Available coalesced events are read, followed by the delivered event; the actual release position is retained. Raw capture is bounded to 4,096 samples. Fitting runs on release/options/Finish, not every sample. Preview redraws once per delivered event; this is not a zero-allocation claim.

An iterative Douglas–Peucker pass retains samples within half the chosen tolerance of simplified segments. Tangent-derived cubic handles shrink into a convex corridor within the other half, with endpoint projections restricted to the segment. Independent handles permit reduced rounding at sharp turns. Controls are then mapped through the inverse parent world transform, preserving the displayed outline under affine parents. More than 256 anchors rejects the fit. Worst-case simplification is quadratic within the finite sample limit; no large-scene/mobile performance claim is made.

[Deterministic fitting experiments](../research/results/studio-freehand/fitting.json) report anchor counts, sampled deviation and elapsed fitting time for waves, rings, corners and noise. Deviation is estimated against 128 linear subdivisions per cubic; it is not a measured comparison with an Editor-produced curve or a certified error bound on continuous human input. The corridor argument concerns retained input samples and their connecting polyline; sub-threshold movements and unsampled hardware motion are outside it.

## Original example and verification

[Wisp source](../apps/web/assets/examples/wisp.evir-project), [compatible export](../apps/web/assets/examples/wisp.riv) and its actual Canvas poster form a seventh public feature study. Organic body/wing outlines are generated sample loops fitted by the same freehand code, with deterministic point IDs. They are not a recording of a human drawing. Solid mint/peach/forest shapes and an existing Drift animation introduce no unsupported rendering features or borrowed artwork. Open the study, select **drawn body**, then **Edit points** to inspect the reduced anchors.

`npm run test:editor` includes seven freehand unit checks and five browser sizes (320, 390, 844 landscape, 1024 and 1440). The tasks cover draft isolation, affine parenting, bottom-sheet validation/focus, minimum topology, complexity limits, keyboard shortcuts, cancellation/blur/pointer ownership, touch drawing/navigation, one-step undo/redo, independent point edits, downloaded source, recovery and automated accessibility. The exact browser-downloaded `.riv` is compared with Evir Canvas pixels using official Canvas2D and WebGL2 2.44.0 runtimes. `npm run validate:editor` retains the broader authoring regressions. `npm run test:web` checks all seven study round trips and selected animation/runtime pixels. [Fresh evidence](../research/results/studio-freehand/) records the actual commands, screenshots, source/export hashes and software-graphics diagnostics.
