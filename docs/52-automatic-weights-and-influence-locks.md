# Automatic weights, smoothing and influence locks

21 October 2026. The retrieved [Rive bones guide](../research/software-closure/sources.json) describes nearest-bone automatic assignment, blending, maximum influences, neighboring-vertex smoothing and locking a vertex's influence for a specific bone. The pinned runtime Weight implementation stores four byte-valued influences. These establish the workflow and encoding. Rive does not specify its exact automatic-weight distance kernel in that guide. Evir's bounded inverse-square kernel is a product choice; it is not claimed to reproduce Rive Editor's weight assignment. Blender documentation requests returned 403 and provide no evidence.

## Studio workflow

Select a bound path/mesh and open **Skin weights…**. Choose a bone, a numbered vertex and the anchor/handle scope. **Lock bone influence on vertex** freezes that bone's weight for the selected control(s). A mixed checkbox means only some handles are locked. Locks are committed immediately with their own Undo, just like the existing numeric weight action. Other bone weights share the remaining budget; an impossible numeric request rejects without a partial edit. Brush painting skips locked target controls and clamps its target to the available remainder.

**Automatic weights…** opens a separate bottom sheet. Choose the entire shape or one numbered vertex, control scope, Blend and Maximum bone influences. Preview reports the source controls that would change and the preserved lock count. Cancel changes nothing; Apply makes one Undo step. Bind segments use their stored bind matrices and current authored bone lengths. Zero Blend selects the nearest unlocked segment rigidly. Positive Blend uses inverse-square distance with a softness radius based on mean segment length. Relative scores avoid numerical underflow for distant finite controls. Existing positive locks consume influence slots; the tool rejects a maximum that cannot accommodate them.

**Smooth weights…** averages neighboring controls, with strength and 1–10 simultaneous iterations. Path neighbors stay within each contour; mesh neighbors come from triangle edges. The same subset, preview, cancellation and Undo rules apply. Each operation accepts up to 4,096 selected vertices; a numeric vertex scope works on larger layers. Weight tools operate on at most four bound bones. Existing imported bindings outside that editing limit are retained; explicitly rebind a subset before editing them with these tools.

Use the original Kelp example to inspect **hello tendril**, try soft automatic weights, lock a joint's anchor influence and smooth the other assignments. Gust provides a textured mesh as a second original test case. Binding choices now have search and 24-item pages rather than mounting every bone. Chosen bones persist across pages; Clear chosen bones only changes the binding draft. Rebinding explicitly resets weights and removes the layer's locks. Unbinding or deleting a layer/control also removes its lock references; Undo restores them.

## Source and command contracts

Optional source v3 `editor.weightLocks` stores `{nodeId,pointId,control,boneId}` records. Controls are anchors, incoming handles or outgoing handles; meshes use anchors and synchronize all three weight slots. References, duplicates, the 65,536-lock budget and byte-quantized locked rows are validated. Setting a lock canonicalizes that control to the exact bytes already used by native rendering. Runtime snapshots and `.riv` omit editor metadata. Locks do not become runtime constraints or survive a native-only round trip.

`setSkinLocks`, `autoSkinWeights`, `smoothSkinWeights` and `unbindSkin` share model validation, owner locks and atomic history. Residual normalization preserves locked bytes exactly and distributes the remainder deterministically. Previews share immutable history records and copy changed weight rows, while cached neighbor lookups bound smoothing allocations. Weight-tool reads use History’s deeply frozen `readCommitted()` version rather than cloning the full project and embedded assets for each stats update. Existing mutable `snapshot()` / `committed()` contracts remain unchanged.

The typed local command schema exposes `set_skin_locks`, `auto_skin_weights` and `smooth_skin_weights` alongside binding/manual weights and IK. Empty point-ID selection means the whole shape; a supplied subset must reference existing controls. These commands use the existing opt-in local session and its revision/lock/retry/one-Undo rules. They add no hosted service or remote pairing.

## Evidence and limits

[Unit tasks](../tests/editor/skin-tools.test.mjs) check nearest/soft assignment, exact frozen bytes, impossible residuals, source/native isolation, serialization, history, topology/subsets, independent compound contours, mesh adjacency, brush handling, distant-coordinate influence limits, malformed-import diagnostics and immutable previews. [Tracked source/native downloads](../research/results/software-closure/skin-tools/) support reproduction. Native comparisons verify the resulting scene's deformation and rendering; they do not establish identical automatic assignment to Rive Editor.

Cloud automation does not replace postponed physical tests or the outstanding human/assistive-technology sessions. Broader nested blending, nonunit IK and animation rebasing remain separately tracked.
