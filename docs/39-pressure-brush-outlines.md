# Pressure-aware brush outlines

Research and implementation: 15 October 2026. This is an authoring extension to Freehand, hosted by the same web app. It changes no engine schema or native stroke contract.

## Research and scope

The [Pointer Events specification](https://www.w3.org/TR/pointerevents3/#dom-pointerevent-pressure) defines normalized pressure, a midpoint fallback for hardware without pressure and zero when no buttons are active. Coalesced events expose additional movement samples. A release event must not overwrite the last active tip pressure with zero. Evir consumes pressure from active pen events, including coalesced input; mouse and touch deliberately use 0.5. A pen driver without pressure may also return a constant midpoint. Physical stylus behavior remains untested, as requested.

[Rive's fill/stroke documentation](https://rive.app/docs/editor/fundamentals/fill-and-stroke) describes separate stroke paints with width, caps, joins and optional gradients. Evir's existing path contract is filled cubic geometry. This increment therefore generates a **closed filled outline**, rather than introducing native stroke paints. The [perfect-freehand documentation](https://github.com/steveruizok/perfect-freehand#readme) describes explicit pressure input and outline construction. Evir pins its MIT-licensed version 1.2.3, disables simulated pressure, uses round caps, no streamline displacement and fixed thinning of 0.65. The package license ships in Studio's `assets/LICENSE.perfect-freehand`. Exact response hashes, unsuccessful discovery URLs and the installed implementation hash are in the [source register](../research/pressure-brush/sources.json).

These are explicit product choices, not evidence of matching Rive's stroke renderer, trim paths or handwriting quality. The external library constructs an outline; Evir's existing bounded cubic fitter reduces that outline to editable controls. The chosen fit tolerance applies to the generated outline samples, not to a physical pressure trace or a certified swept-disc union. Self-crossing strokes keep ordinary nonzero fill behavior; no boolean union/cleanup contract is added.

## Draw and review

1. In **Design**, choose **Freehand** or press **B** outside a text field. Select a visible unlocked group or bone first if it should parent the new path.
2. Open **Drawing options**, choose **Brush outline**, set **Width (artboard units)** from 1–256 and optionally enable **Use pen pressure**. Width is nominal: midpoint pressure gives the chosen width, while active pressure changes it. Disable pressure for a constant width. Mouse/touch always retain the nominal width.
3. Apply, then drag with a pen, mouse or one finger. The live preview shows the filled outline. Release to review editable points.
4. Reopen options to change width, pressure or smoothing and refit the same draft. **Keep drawing** or Escape discards option changes. An invalid or over-budget fit leaves the previous draft and settings available.
5. Choose **Finish path** or Enter. This creates one ordinary filled path in one undo step. **Edit points**, fill colors/gradients, compatible animation, source saving, browser recovery and `.riv` export then work normally.

Width and pressure are baked into the outline when finished. They are not retained as native stroke properties, a centerline or raw hardware samples. Later edits use the outline controls; draw another stroke to choose a different brush width. **Filled shape** mode retains the previous closure controls and implicit-fill behavior. Switching styles refits only a valid released draft. Bottom sheets retain focus, Escape/cancel, custom errors, sticky title/actions, compact full-width layout and reduced-motion transitions. Existing Pen and numeric point controls provide discrete authoring alternatives; this is not a screen-reader usability claim.

A tap is rejected with custom feedback. Escape, Undo, Backspace or Cancel discards a pending draft. Capture loss, cancellation, blur, resize and a second finger retain the existing Freehand rollback behavior. Drafts block incompatible edits, saves and mode changes. Another pointer cannot contribute to the owning gesture. Options are session preferences and raw samples are transient; neither enters the saved scene or runtime file.

## Bounds and evidence

Capture retains at most 4,096 finite world-coordinate/pressure samples. Small movement is filtered at 0.75 screen pixels unless pressure changes by at least 0.02; stationary input updates its last pressure without accumulating duplicate positions. Coalesced events and the delivered event are consumed, and the final release position retains the prior active pressure. Brush construction runs once per delivered preview event and on fitting, within the capture bound. It is not a zero-allocation or device-performance claim.

The generated outline must also fit within 4,096 samples and 256 cubic anchors. Complexity is rejected without silently increasing tolerance. Smoothing remains 0.5–8 screen pixels at the draft's original zoom. World-space outlines map through the inverse parent transform, preserving width and position under affine groups. Extremely thin/over-smoothed strokes may need lower smoothing or a larger width to retain valid filled area. General animated-parent rebasing and new skin weights are separate contracts.
